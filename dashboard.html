Filter
Funnel
Stage distribution across every lead in the current filters, with no age or grace gating. Closed leads have left the funnel and appear in the Exited row rather than in a stage band — bands plus Exited reconcile to the total. The Operations tab counts only what is actionable, so its numbers are smaller by design.
Daily Lead Volume
Leads created per day, from lead_created_at. This is genuine history — unlike SLA-compliance-over-time, which would need stored snapshots the dashboard doesn't keep.
SLA Compliance Trend
Share of open leads breaching at least one SLA check, one snapshot per day this dashboard was connected. Captured locally in this browser only — not a server-side log, so it won't reflect days nobody opened the page, and it resets if browser data is cleared.

Inactive-RM Lead Added
New leads created today that landed on an RM currently marked inactive (rm_is_active) — nobody can work these until they're reassigned. Only checkable for today's leads, since rm_is_active is a current snapshot, not a historical record — this can't tell you whether an older lead was misrouted, only that a fresh one just was.
Not Updated
Open leads still sitting in "Not Updated", aged 3–48 hours. Deliberately narrower than the Funnel's Not Updated band, which shows every lead in that stage including closed ones, leads under the 3h grace, and leads past 48h (those appear under Stuck instead). Also includes any open, under-48h lead that has never connected at all past the 10-minute first-contact window, regardless of its stage text — see Not Connected in 10 Minutes below for the leads that DID eventually connect, just late.
Not Connected in 10 Minutes
A retrospective SLA-miss marker: open, under-48h leads that DID connect, but only after the 10-minute first-contact window had already passed. A lead that still hasn't connected at all isn't shown here — it's filed under Not Updated above instead, since "nothing has happened yet" is a different signal from "we got there late."
Calls Made — Not Logged in CRM
SOP Rule 3 — CRM logging after each attempt. Open leads where call_attempts has pulled at least 3 ahead of dated CRM comments — calls are happening but the write-up isn't. The mirror case (comments with no calls at all) is covered separately under Recording Not Working below. Like Recording Not Working, this is a data-integrity view only — not part of the Issues CSV, region email reports, tab badge count, or RM SLA Score.
Follow-up Overdue (4h Post-Connect)
SOP Rule 4 — once connected, CRM must be reviewed every 4 hours. Applies regardless of call count, so well-called leads that have gone quiet still surface here.
Behind on Today's Calls
Open leads (not closed, not Opportunity+) with fewer than 5 call attempts made TODAY (IST), past grace. For a lead created today, today's effort is the call_attempts column directly. For an older lead still open, there's no true per-day counter in the export, so this counts CRM-log entries timestamped today as the closest available proxy — undercounts if a real call wasn't logged as a comment.
Leads Pending Beyond 48 Hours (Not Yet Opportunity)
Open more than 48 hours and still hasn't reached Opportunity stage — regardless of how many calls were made. A different problem than under-calling: these got worked, but haven't converted.
Recording Not Working
Call count is zero but work exists, or a lead was closed with nothing recorded at all. Deliberately unfiltered: no open/closed check, no grace period, no priority ranking.

Per-region To / Cc, used automatically by every Send button below. A combined-region email (see the checkbox above) uses the union of every region it covers. Comma-separate multiple addresses. Saved in this browser only.
One-time setup for real one-click sending via the Gmail API — no backend, no stored secret (a Client ID is a public identifier, safe to keep in this browser). It needs this dashboard served over http/https — Google sign-in does not work from a local file:// page, so this won't connect while opened as a local file.

1. Google Cloud Console → APIs & Services → Credentials → Create OAuth client ID → type Web application.
2. Under Authorized JavaScript origins, add the exact origin this page is served from (e.g. https://yourteam.example.com — no path, no trailing slash).
3. APIs & Services → Library → enable the Gmail API for that same project. If you also want the Movement tab's "Snapshot on refresh" feature, enable the Google Sheets API too (same Library page) — that feature uses this same Client ID but its own, separate consent grant.
4. OAuth consent screen → add each RM's Google account as a Test user (Testing mode covers up to 100 users, no Google review needed) — or set the app type to Internal if this is a Google Workspace account.
5. Paste the Client ID below and connect. Each person sends as their own signed-in Google account.

Updated Leads
A lead counts as updated when its last_connect_time falls in the window, or when a comment in internal_status_comments carries a timestamp in the window. Periods are combined, so Today + Yesterday returns both days. The tab respects the filters at the top of the page.

Stalled Flagged Leads
Compares two snapshots captured by a small Apps Script that runs every 6 hours, independently of this dashboard — see MovementTracker.gs. "Moved" means stage changed, call attempts increased, or a new CRM comment was logged; a lead only appears here if it was flagged at the "To" snapshot AND nothing changed since "From". Respects every filter above — Project/Region/TL/Source/Sub-source and the Created date range.

Overnight Leads

RM Stall Leaderboard
Every zero-movement gap across the WHOLE retained snapshot history (up to 7 days) — not just the one pair picked above — so a lead that sat untouched for 3 consecutive checks counts 3 times, weighting by how long it actually sat. Respects the Project/Region/TL filters above.
Time to Remediate

Only counts stalls that resolved within the retained history — one still stalled right now isn't in here yet (it's in the leaderboard above while it's ongoing).
