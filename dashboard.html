Updated Leads
A lead counts as updated when its last_connect_time falls in the window, or when a comment in internal_status_comments or stage_comments carries a timestamp in the window. Periods are combined, so Today + Yesterday returns both days. The tab respects the filters at the top of the page.
Activity by Hour of Day
Same period picker as Updated Leads above (and the same filters at the top of the page) — every logged touch in that window, bucketed by hour of day in IST, so you can see when leads are actually being worked: morning, afternoon, or evening. Comments are individual dated log lines (one per call attempt/note, from the same parsing Updated Leads uses); Call connect is each lead's single most recent connect timestamp, so it's a thin top layer, not a full call log — Comments carry the real volume.

Respects the Project/Region/TL filters above.
Time to Opportunity (approx.)
Approximates how long it takes a lead to reach Opportunity+, using the same Movement_Log snapshot history as Time to Remediate above — the schema has no stage-entry timestamp, so this is duration from lead_created_at to the first retained snapshot where the lead already reads as Opportunity+, not the true crossing instant. A lead already Opportunity+ at its own earliest retained snapshot is excluded, not counted at that first-seen time — its true crossing could have happened long before retention began, and counting it anyway would understate the fastest conversions specifically. Respects the Project/Region/TL filters above.
Unmatched Comments
Every DISTINCT comment anywhere in the whole captured Movement_Log history that the keyword-based follow-up logic (inferOutcome) couldn't classify — real notes an RM wrote that fall through every known keyword and get the generic "no keyword match" fallback instead of a real suggested action. Whole history, every project/region/TL/source — not scoped to the filters above, since the point is finding phrasing worth teaching the keyword list, not listing leads needing action right now. Deduped by exact comment text, so a note repeated across many snapshot captures for the same lead only counts once.

Region Issue Trend
Reads the same Movement_Log sheet tab as the Movement tab below — nothing here is stored in this browser, so any pair of captured snapshots reads identically for anyone who opens this Sheet. Pick a "From" snapshot (e.g. right when you sent a region's email) and a "To" snapshot (e.g. now); the chart and table below show ONLY that range, grouped the same way the region emails are grouped (mainRegionFor(effectiveRegion())). If a day has several captures (the 6-hourly trigger plus any manual Snapshot now clicks), the connected line plots that day's latest one — every other same-day capture still shows, but only as a small dim dot in the background. Hover a line or dot to see which issue it is and its exact value; date labels include the day of week. New comparison points come from either MovementTracker.gs's automatic every-6-hours capture, or the Snapshot now button up in the header. The top mini-chart (bright green) is Total Leads in System — every matching lead at that snapshot, any stage, not just open ones — so you can tell whether an issue count dropped because it was actually worked down or just because overall volume shrank; the table's % columns divide each row by that same total.
Same-Cohort Progress
The table above compares raw totals at From vs. To — as new leads keep getting added, "Total Leads in System" keeps growing, so a rising or flat issue count doesn't necessarily mean nothing got worked on. This table answers a narrower question instead: of the leads that existed at BOTH the From and To snapshots (matched by lead_id, brand-new leads excluded entirely), how many that were flagged for each issue at From are still flagged for that SAME issue at To? That isolates genuine progress on leads you were already tracking from the effect of new volume.
0–48h Cohort Outcome (approx.)
Answers the 0–48 Hour Funnel Audit's core question with a real cohort instead of a live snapshot: of leads CREATED in the Created-date range set in the filter bar above (not the From/To snapshot pickers above), how many reached Opportunity+, closed without converting, or were still open at their OWN personal 48-hour mark — read from the closest retained Movement_Log snapshot to that moment, up to ~6h resolution either side. Leads still under 48 hours old right now are excluded from every rate shown (an incomplete cohort would understate the failure rate), and every number is approximate by construction — Movement_Log retains 7 days, so this only covers leads created recently enough for their 48h mark to fall inside that window.
Daily Cohort by Region
Pick one specific day (not a range): of the leads CREATED that day, per region — Same-Day Opp% (reached Opportunity+ by the end of that day, or as of right now if the day's still in progress), 48h Opp% and 48h Close% (status at each lead's own 48-hour mark, once it's elapsed — fully available for every lead roughly 2 days after the picked date), and how many of the region's leads that 48h figure is actually based on so a partial cohort is visible, not hidden. Same evidence method as 0–48h Cohort Outcome above (closest retained Movement_Log snapshot, live sheet as fallback).
